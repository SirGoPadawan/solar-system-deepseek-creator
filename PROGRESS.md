## Что это

Демо-сцена на Three.js (r186): Солнечная система с процедурными текстурами планет,
фоновой туманностью, звёздным полем и дрейфом всей системы по спирали в космосе.

## Файлы проекта

- `index.html` — точка входа, importmap указывает на **`vendor/three/`** (не на `node_modules`).
- `src/styles.css` — **все стили интерфейса** (панель, карточка планеты, подсказка, виньетка).
- `index.js` — **тонкая точка входа**: `import './src/main.js'`. Вся логика вынесена в `src/`.
- `src/config.js` — все настройки: планеты (с именами/спутниками/аппаратами), пояса, кометы,
  Тесла, шаги скорости UI, глобальные константы.
- `src/noise.js` — математика шума (value-noise, fBm), палитры-градиенты, `paintPixels`.
- `src/textures.js` — процедурные текстуры планет, туманность, маска-свечение.
- `src/orbit.js` — **орбитальная механика**: Кеплер, эллипсы, наклон плоскостей орбит.
- `src/bodies.js` — планеты, спутники, аппараты, кольца, атмосферы, Солнце (корона), Тесла.
- `src/belts.js` — пояса астероидов и Койпера: `InstancedMesh`, неровные камни, эллипсы.
- `src/sky.js` — звёздное поле (стрим), сфера-туманность, свечение фона, объёмный туман.
- `src/grid.js` — сетка эклиптики в плоскости Солнца.
- `src/galaxy.js` — процедурная галактика «Млечный Путь» (балдж-бар, рукава, HII, пыль, свечение звёзд).
- `src/blackhole.js` — чёрная дыра в центре: сфера Шварцшильда, фотонное кольцо, аккреционный диск.
- `src/systems.js` — другие звёздные системы в рукавах (генерация + сборка + анимация).
- `src/planetInfo.js` — тексты карточки (описание, факты) и данные подсказки (масса/темп/атмосфера).
- `src/trails.js` — аналитические винтовые следы.
- `src/comets.js` — кометы с хвостами и Tesla Roadster (Starman).
- `src/ui.js` — панель управления: скорость, тумблеры, список планет, выбор системы.
- `src/card.js` — карточка планеты над планетой (2D-слой, привязан к проекции).
- `src/tooltip.js` — футуристичная подсказка при наведении (2D-слой).
- `src/main.js` — сборка сцены, свет, игровой цикл, raycast-выбор и наведение.
- `server.js` — статический сервер без зависимостей (для `npm start`), ESM.
- `tools/check.cjs` — проверки без браузера (`npm run check`): синтаксис, импорты, API three, методы.
- `tools/galaxy.test.cjs`, `tools/systems.test.cjs` — смоук-тесты (`npm test`) реального кода

- `vendor/three/` — закоммиченный three.js (`three.module.js`, `three.core.js`) + `addons/controls/OrbitControls.js`.

## Как запускать

Одной командой:

```bash
npm start
```

Открыть: http://localhost:8000 (обновлять через Ctrl+F5, чтобы сбросить кэш).
Другой порт: `PORT=3000 npm start`. Остановить — Ctrl+C.

Проверено: `npm start` поднимает `server.js`, отдаёт `index.html`, `index.js`,
`three.module.js` с корректным `Content-Type: text/javascript` (иначе ES-модули не грузятся).

## Проверка проекта одной командой

```bash
npm run check
```

Скрипт `tools/check.cjs` (без зависимостей, работает на Node 12) проверяет:

1. **синтаксис** всех JS-файлов (`node --check`);
2. **связи импортов** — что каждый `src/*.js` действительно экспортирует то, что у него просят;
3. **API three** — что все `THREE.X`, которые мы используем, есть в вендорном бандле;
4. **методы** — что каждый вызов `.<метод>()` в `src/` есть либо в three, либо в наших
   объектах/браузере (белый список своих и DOM-методов — в `tools/check.cjs`).

Пункты 3–4 появились после реального бага: в `src/galaxy.js` был вызван `THREE.Color().mix()`,
которого в three r186 **нет** — сцена падала ещё до первого кадра (класс есть, метода нет).
Проверка сразу это ловит:

```
[4/4] методы объектов (вызовы .имя())
  ✗ src/galaxy.js: нет метода .mix() ни в three, ни в наших объектах
```

Поэтому любое новое обращение к API three стоит прогонять через `npm run check`.

Полный прогон (проверки + смоук-тесты) — **`npm test`**:

```bash
npm test        # 1) check.cjs  2) galaxy.test.cjs  3) systems.test.cjs
```

Смоук-тесты запускают **настоящий код** `src/galaxy.js` и `src/systems.js` на минимальной
заглушке three (классы `Vector3`/`Euler`/`Color`/`Group`/`Points`/… с честной математикой
`applyEuler`). Они ловят то, чего не видит `node --check`: несуществующие методы, опечатки,
`NaN` в массивах вершин и нарушение геометрии. Самая ценная проверка:

- `tools/galaxy.test.cjs` — **Солнечная система обязана лежать в плоскости диска** галактики
  (проекция центра диска на нормаль = 0), иначе Млечный Путь «провалился» бы или встал стенкой;
  чёрная дыра стоит ровно в локальном `(0,0,0)`, её диск быстрее галактики и реально крутится;
  плюс проверяется, что `dispose()` реально освобождает геометрию, а 12 случайных галактик
  собираются без ошибок;
- `tools/systems.test.cjs` — генерация систем (дистанции от Солнца, 1–5 планет, орбиты по
  возрастанию, конечность чисел), сборка объектов, 100 шагов анимации без `NaN`, `dispose()`.

### Этап 2. Полностью новые процедурные текстуры
Раньше были плоские кружки и жёсткие полосы («нулевые»). Заменено на шум:
- value-noise + fBm, сглаживание, палитры-градиенты, расчёт **по каждому пикселю** через `ImageData`.
- **Бесшовность по горизонтали** (координаты заворачиваются по модулю периода) — нет шва на сфере.
- Индивидуальная текстура на каждую планету:
  - Солнце — грануляция фотосферы;
  - Меркурий — серый, кратеры/бассейны;
  - Венера — горизонтальные вихри облаков;
  - Земля — океан/суша по порогу высоты, лёд на полюсах, отдельный слой облаков (океан ~2/3);
  - Марс — ржавые равнины + небольшие полярные шапки;
  - Юпитер — контрастные пояса + зональные потоки + **Большое Красное Пятно** (оверлей);
  - Сатурн — мягкие кремово-золотые пояса.
- **Разрешение текстуры зависит от размера планеты**: `textureSize(radius)` →
  1024 (Солнце) / 768 (гиганты) / 512 (мелкие). Экономит время генерации (~1.1 c вместо ~2.2 c).
- Кэш текстур по ключу `тип@размер`.
- Звёзды: разброс по сферической оболочке, цветовой разброс, аддитивное смешивание, `depthWrite:false`.

### Этап 3. Туманность и дрейф по спирали
- Корневая группа `world` — содержит всю систему (планеты, орбиты, свет `sunLight`/`rimLight`, ореол).
- **Туманность**: сфера радиусом 600 (`BackSide`, `toneMapped:false`, `depthWrite:false`);
  текстура из «гребневого» fBm + низкочастотный выбор оттенка (бирюза → фиолет → маджента).
- **Дрейф по спирали** в `animate()`: `world` движется по винтовой траектории (`x/z` — виток,
  `y` — покачивание) + лёгкий наклон `rotation.x/z`.
- Звёздное поле и туманность плывут навстречу (параллакс → ощущение полёта).

### Этап 5. Полёт сквозь космос + винтовые следы (по референсу solar.jpg)
Референс `solar.jpg` в корне проекта: система летит вперёд, планеты оставляют спиральные следы,
камера-наблюдатель стоит на месте.

- **Убрано прежнее круговое движение `world`** (спираль теперь передаётся следами, а не дрейфом группы).
- **Камера статична** — движение системы наблюдатель видит за счёт фона.
- **Бесконечное звёздное небо**: звёзды разложены равномерно в кубе `STAR_BOX` и каждый кадр
  сдвигаются против `MOTION_DIR` с оборачиванием координат в кубе (`wrapBox`) → небо стримится
  навстречу бесконечно, без «улетания» системы из кадра.
- **Винтовые следы** для Солнца и всех планет (`updateTrails`): след строится **аналитически** —
  берётся орбита тела за прошедшее время `TRAIL_TIME` и точки смещаются назад на `MOTION_SPEED*age`.
  Итог: орбита + полёт = спираль (винт). Солнце (distance 0) даёт прямую золотую нить.
  Цвет затухает к хвосту (`vertexColors` + `AdditiveBlending`).
- Параметры полёта: `MOTION_DIR`, `MOTION_SPEED`; следы: `TRAIL_TIME`, `TRAIL_POINTS`, `trailColors`.

### Этап 6. Наклон системы и ускорение
- **Наклон всей системы**: `world.rotation.set(SYSTEM_TILT_X, 0, SYSTEM_TILT_Z)` — плоскость орбит
  встала под углом к направлению полёта (больше не «летит на тарелке»).
- Важно: наклон применяется **и к следам** (`trailVec.applyEuler(systemTilt)`), иначе следы разъедутся
  с планетами (они считаются аналитически в локальных координатах).
- Скорость полёта: `MOTION_SPEED` 4 → 5.5.

### Этап 7. Правильный наклон: спирали ⟂ система
- Проблема была в том, что направление полёта **не совпадало с нормалью плоскости орбит**, поэтому
  спирали уходили «вбок», а плоскость выглядела плоской («тарелка»).
- Теперь `MOTION_DIR` **вычисляется как нормаль плоскости орбит после наклона**:
  `(0,1,0).applyEuler(SystemTilt)`. Значит следы всегда идут перпендикулярно системе.
- Наклон изменён на `SYSTEM_TILT_X = 0.15`, `SYSTEM_TILT_Z = 0.6` — плоскость читается как
  наклонённый диск (эллипсы), проверено: сжатие орбит ≈ 0.49 при данной камере.
- Важно: если менять `SYSTEM_TILT_*`, `MOTION_DIR` пересчитывается автоматически (он производный).

### Этап 11. Солнце, кометы, Тесла, туманность, UI и разбиение на модули
Крупный проход: новые объекты + интерфейс + рефакторинг `index.js` на модули `src/`.

**Солнце** `[FEATURE:SUN]`:
- Тёмные **пятна на фотосфере** (`drawSunspots` — оверлей поверх текстуры).
- Материал Солнца — `MeshBasicMaterial` с `toneMapped: false` (не «выцветает» от тонмаппинга).
- **Корона** `createSunCorona` — шейдерная fresnel-оболочка (`radius*1.22`), «дышит» (`uTime`),
  медленно проворачивается.
- Два **ореола**-спрайта (`glow`, `glowOuter`), пульсируют по размеру. Всё крепится к `sunMesh`.

**Кометы** `[FEATURE:COMETS]` — 3 штуки (`COMETS`):
- Ядро (icosahedron) + кома (спрайт) + **хвост** линией с вершинными цветами.
- Движение по эллипсу (Кеплер-подобно): у перигелия быстрее (`dnu ∝ a²/r²`, ограничено `0.15`).
- Хвост всегда направлен **от Солнца** и растёт при сближении. Свою линию орбиты рисует `createEllipseOrbit`.

**Tesla Roadster со Starman** `[FEATURE:TESLA]` — `buildTesla`:
- Красный кузов, стеклянная кабина, 4 колеса, белая фигурка в шлеме, деликатное свечение.
- Гелиоцентрическая орбита с эксцентриситетом (`a≈17.5, e≈0.32`), кувыркается в невесомости.

**Туманность** `[FEATURE:NEBULA]` (переработка текстуры):
- Палитра `NEBULA_HUE`: синий → бирюза → фиолет → маджента → тёплый.
- Шейдер: **галактическая полоса** (изогнутая шумом), гребневые волокна, яркие ядра,

### Этап 13. Орбитальная механика: Кеплер, эллипсы, наклоны, вращение `[FEATURE:KEPLER]`
Четыре правки от заказчика — «сделать движение честнее»:

1. **Скорость по Кеплеру.** Угловая скорость больше не задаётся руками, а считается
   по третьему закону: `n = SPEED_FACTOR / sqrt(R³)`, где `R` — радиус орбиты (большая
   полуось `a`). `SPEED_FACTOR = 0.21` подбран под масштаб сцены (аналог `GM`).
   В итоге Меркурий делает оборот за ~7 с, Нептун — за ~94 с (отношение периодов 13.5
   ≈ (33/5.8)^1.5 — как в природе).
2. **Эллиптические орбиты.** Позиция считается по фокусу: `r = a·(1 − e²)/(1 + e·cos ν)`,
   затем `x = cos ν · r`, `z = sin ν · r`. Наибольший эксцентриситет у Меркурия (0.206),
   у Марса (0.093), у Земли (0.017). Линия орбиты рисуется по тем же точкам.
3. **Наклон плоскостей.** У каждой планеты свой `inclination` (0–7°, реальные значения)
   и `node` — долгота восходящего узла. За счёт наклона у орбит появляется смещение по Y,
   и в 3D видно, что планеты не лежат в одной плоскости.
4. **Осевое вращение.** `spinSpeed` свой у каждой планеты, у **Венеры отрицательный** —
   ретроградное вращение (крутится в обратную сторону).

Вся математика — в отдельном модуле `src/orbit.js` (`meanMotion`, `orbitRadius`,
`orbitLocal`, `orbitOrientation`, `orbitPolyline`), чтобы анимация (`main.js`) и следы
(`trails.js`) считали одно и то же и не разъезжались.

### Этап 15. Фоновая спиральная галактика `[FEATURE:GALAXY]` (`src/galaxy.js`)
Процедурная спиральная галактика вокруг Солнечной системы — одна система частиц на весь фон.

1. **Один draw call.** `THREE.BufferGeometry` + `THREE.Points`, **80 000** звёзд-точек.
   Позиции и цвета — типизированные `Float32Array`, геометрия статичная (в кадре меняется
   только поворот объекта), поэтому стоимость близка к нулю.
2. **Математика рукавов.** Изолированная (чистая) функция `generateGalaxyPoints(options)` —
   только числа и цвета, без THREE-объектов, вызывается и сама по себе. Параметры:
   - `branches` — число рукавов (4);
   - `radius` — внешний радиус диска (380);
   - `spin` — коэффициент закручивания (1.15 оборота от центра к краю);
   - `randomness` / `randomnessPower` — разброс поперёк рукава (0.26 от радиуса, степень 2.2 —
     мелких смещений много, крупных мало), из-за чего рукава плавно расширяются и рассеиваются к краям;
   - `thickness` — толщина диска (растёт к краю, рукава «пухнут»).
   Координаты: `x = cos(branchAngle + spinAngle)·r + rnd()`, `z = sin(...)·r + rnd()`,
   где `spinAngle = (r/radius)·spin·2π`. Есть предохранитель: звезда, попавшая внутрь
   `innerRadius`, отодвигается на его границу — рукава физически не могут залезть в планеты.
3. **Интерполяция цвета** через `THREE.Color().lerp()`: ядро (тёплое бело-жёлтое `0xfff1c9`) →
   середина (голубая `0x8fb4ff`) → концы рукавов (глубокий синий/фиолетовый `0x5b2bd6`).
   Плюс каждой звезде свой коэффициент яркости, чтобы скопление выглядело живым.
   > ⚠️ В three r186 у `Color` **нет** метода `mix()` (`mix` есть в других движках/версиях);
   > ровно тот же смысл даёт `lerp(color, alpha)`. На этом сцена однажды падала целиком —
   > теперь API проверяется командой `npm run check`.
4. **Медленное вращение.** `update(delta, motionScale)` крутит именно `points`
   (`points.rotation.y += rotationSpeed · delta`, по умолчанию ≈ 0.001 за кадр при 60 fps),
   а наклон диска живёт на группе — структура рукавов не деформируется.
   Вращение согласовано с паузой и тумблером «Движение системы».
5. **«Другая галактика»** — кнопка 🎲 в блоке «Галактика». `randomGalaxyConfig()` берёт одну из
   пяти палитр (`GALAXY_PRESETS`: Классика, Ледяная, Розовая, Изумруд, Уголёк) и разбрасывает форму:
   рукавов 2–7, закрутка 0.55–1.9, радиус 260–520, случайные `randomness`, толщина и наклоны.
   Старая галактика честно освобождается через `dispose()` (геометрия + материалы; общие текстуры
   `starTexture`/`glowTexture` не трогаем). Текущие параметры видны строкой в панели.
6. **Вид снаружи** — кнопки 🌀 «Вид» и 🪐 «Система». Мы находимся **внутри** галактики, поэтому
   целиком её не увидеть: камера плавно отлетает по нормали диска (`getNormal()`, взята чуть «в три
   четверти») на 1250 единиц и обратно. Полёт — `easeInOutQuad` в цикле анимации, на время полёта
   управление отдаётся камере. Когда камера дальше 460 от центра, сферический скайбокс (звёзды,
   туманность, свечение) прячется — снаружи он выглядел бы как «стенка»; туман при этом не
   выключается, а обнуляется по плотности, чтобы не пересобирать материалы.

Детали: `sizeAttenuation: false` (точка одинакова и вблизи, и вдали — иначе звёзды у камеры
превратились бы в «блины»), аддитивное смешивание, `fog: false` и `toneMapped: false`
(иначе туман и тонмаппинг съедают цвет). Тумблер «Показывать» и три кнопки в блоке «Галактика».
Дальняя плоскость камеры увеличена 1000 → 6000, `maxDistance` OrbitControls 200 → 1600.

### Этап 16. Галактика как Млечный Путь + другие звёздные системы `[FEATURE:SYSTEMS]`

Запрос: «добавь несколько систем, и кнопку, чтобы можно было выйти из системы, в которую
провалился, и чтобы по скроллу можно было отдаляться из системы в галактику, и чтобы
сама галактика была как наш Млечный Путь».

#### 16.1 Мы ВНУТРИ диска, а не в ядре

Раньше галактика была фоном вокруг системы: центр в начале координат, а вокруг Солнечной
системы — дырка `innerRadius`. Теперь как в жизни:

- `GALAXY.distance = 400` — расстояние от центра галактики до Солнца (≈2/3 радиуса диска);
- группа галактики смещается так, чтобы мировая точка `(0,0,0)` лежала **в плоскости диска**:
  центр ставится по направлению проекции `-Z` на плоскость диска. Нормаль диска
  перпендикулярна вектору центра, поэтому Солнце гарантированно «внутри» Млечного Пути;
- дырка в центре больше не нужна (`innerRadius` 70 → 10), а галактика читается
  **полосой через небо** — как настоящий Млечный Путь с Земли, с ядром вдалеке.

Инвариант («центр · нормаль = 0») проверяется смоук-тестом `galaxy_v2_test.cjs`.

#### 16.2 Структура Млечного Пути

- **Балдж + центральный бар** (`bulgeShare = 0.16`): вытянутое ядро `barLength × barWidth`
  (0.22 × 0.09 радиуса), звёзды гуще и ярче к центру. Млечный Путь — галактика с баром.
- **2 главных рукава + 2 второстепенных**: у рукавов разный вес (1.55 против 0.55) и разная
  ширина, выбор рукава для звезды — взвешенный случайный.
- **Голубые молодые звёзды** (`youngShare = 0.08`) и **розовые области HII** (`hiiShare = 0.02`)
  сажаются не ровным слоем, а **кучками**: заранее выбираются «гнёзда звездообразования»
  (7 на рукав), и звёзды жмутся к ним — рукава выходят пятнистыми, как на фото.
- **Тёмные пылевые полосы** (`dustShare = 0.16`): отдельный слой точек чёрного цвета с обычным
  смешиванием, идущий по **внутреннему** краю рукавов (смещение против закрутки) + пыль в баре.
  Пыль «гасит» свечение галактики — получаются характерные прожилки. Порядок отрисовки задан
  явно: диск (`renderOrder -0.6`) → пыль (`-0.55`) → свечение ядра (`-0.5`), иначе аддитивные
  звёзды перекрыли бы погашение.
  Пыль **видна только издалека** (проявляется от 130 до 330 единиц по расстоянию камеры до цели):
  вблизи она мазала бы планеты тёмными пятнами.

#### 16.3 Другие звёздные системы (`src/systems.js`)

- `generateSystemSpecs()` — чистые данные без THREE: класс звезды (красный карлик … голубой
  гигант, веса «как в природе»), 1–5 планет, позиция в диске.
- Системы садятся **на рукава** той же формулой, что и звёзды (`armChance = 0.7`), и никогда
  ближе 210 единиц к Солнцу.
- `createStarSystems(parent, specs)` собирает звезду (MeshBasic + ореол-спрайт, `fog: false` —
  иначе с расстояния галактики звезда утонула бы в тумане), планеты на кеплеровских орбитах
  (`orbitLocal`/`orbitOrientation` из `orbit.js` — та же математика, что у Солнечной системы),
  линии орбит, кольца и атмосферы у части планет.
- Родитель — **сам диск галактики** (`galaxy.points`), поэтому системы едут вместе с рукавами.
- Свет: у планет есть лёгкое `emissive` (видны даже без освещения), а в систему, куда мы
  влетели, переезжает общая «гостевая» лампа `visitLight`. Она всегда `visible`, а когда не
  нужна — паркуется в 1e5 единиц: `visible = false` заставляло бы three пересобирать все
  материалы на каждый вход в систему.
- Кнопка 🎲 пересоздаёт галактику **вместе с системами**; `dispose()` освобождает геометрию,
  материалы и личные текстуры (общие `starTexture`/`glowTexture` не трогает).

#### 16.4 Навигация

- Блок «Навигация» в панели: выпадающий список (🌀 Обзор галактики / 🪐 Солнечная система /
  ★ каждая сгенерированная) + кнопки 🎲 «Другая галактика» и 🌀 «Вид галактики».
- Плавающая кнопка **«⬅ Выйти в галактику»** поверх сцены — видна только когда мы внутри
  чужой системы; Esc делает то же самое.
- На карте галактики звёзды систем ловятся **по экранной близости** (радиус 26 px), а не
  рейкастом — они всего пара пикселей. Наведение показывает плашку (класс звезды, число планет,
  каталог), клик — полёт внутрь.
- **Скролл наружу**: отлетел от системы дальше `GALAXY.exitDistance = 640` — автоматически
  вернулся к обзору галактики.
- Галактика вращается, поэтому внутри чужой системы камера каждый кадр сдвигается вместе со
  звездой — иначе система уехала бы из кадра за полминуты.

#### 16.5 Небо едет за камерой

Скайбокс (звёзды, туманность, свечение) теперь в одной группе, которая каждый кадр ставится
в позицию камеры. Раньше при отлёте наружу сферы приходилось прятать (логика `outsideView`),
иначе они выглядели стенкой; теперь небо всегда вокруг нас, а эта логика удалена целиком.

#### 16.6 Ориентир

На карте галактики видно, где мы: голубое пятно-маркер в начале координат
(`homeMarker`, показывается дальше 420 единиц от цели).

Плюс: `viewDistance = radius · 2.3` — дистанция, с которой диск видно целиком;
`maxDistance` OrbitControls поднимается под радиус случайной галактики.

### Этап 17. Звёзды-светлячки `[FEATURE:STARGLOW]` + чёрная дыра в центре `[FEATURE:BLACKHOLE]`

#### 17.1 Почему звёзды выглядели «тёмными пикселями» и «серыми квадратами»

Три причины, все реальные:

1. **Мипмапы.** Точка на экране — 2–4 px, а текстура маски — 64–128 px. GPU
   выбирает верхний мип-уровень, где радиальный градиент уже усреднён в ровный
   полупрозрачный квадрат. Отсюда серые квадраты вместо кружков. Лечится
   `generateMipmaps = false` + `LinearFilter` (сделано в `createStarTexture` и во
   всех новых масках).
2. **`sizeAttenuation: true` у неба.** Небо теперь едет за камерой, поэтому
   звёзды могут оказаться в паре единиц от неё, и `gl_PointSize` раздувался до
   сотен пикселей. Переключили на `sizeAttenuation: false` + `size: 1.7`.
3. **Тёмные цвета.** Яркость цвета вершины была 0.3–1.0 от тёмно-синего
   `armColor` — точка читалась как цветной пиксель, а не как источник света.

Что сделано:

- у галактики своя **круглая маска** (canvas → `THREE.CanvasTexture`): белое
  ядро, короткая светящаяся юбка, полностью прозрачные углы;
- `starBrightness: 1.35` — общий множитель яркости цветов вершин (цвета — это
  float-атрибут, блендинг аддитивный, поэтому >1 допустим);
- самые яркие звёзды **«выгорают» в белый** (`color.lerp(white, …)`) — именно
  это читается как «звезда светится», а не как синий пиксель;
- второй слой **ореола** (`haloSize: 6`, `haloOpacity: 0.16`) на той же
  геометрии (0 лишней памяти): мягкая маска + аддитивность дают каждому
  источнику гало, а ядру галактики — вспышку;
- в материале явно: `color: 0xffffff`, `vertexColors: true`, `transparent: true`,
  `blending: AdditiveBlending`;
- `sizeAttenuation` у галактики по-прежнему **выключен**: мы ВНУТРИ диска,
  расстояния различаются в сотни раз, и с затуханием ближние точки стали бы
  кляксами. Постоянный размер в экранных пикселях = ровная космическая пыль.

#### 17.2 Чёрная дыра в центре спирали (`src/blackhole.js`)

Координаты — локальные `(0,0,0)` группы галактики, то есть **центр Млечного
Пути** (Солнце смещено на `GALAXY.distance`, поэтому мировой ноль — это не центр).

- **Сфера Шварцшильда** — чёрный шар радиусом `radius = 6.5`. Материал
  `MeshBasicMaterial` с `transparent: true`: так three рисует его в прозрачном
  проходе ПОСЛЕ аддитивных звёзд, иначе чёрный шар оказался бы под ними.
- **Фотонное кольцо** — спрайт с тонкой яркой полосой на 0.68 радиуса и
  `depthTest: false`, чтобы кромка сферы его не срезала.
- **Аккреционный диск** — `RingGeometry` в плоскости диска (XZ) с радиальным
  градиентом: раскалённый внутренний край → оранжевый → красный → прозрачный.
  UV у `RingGeometry` — плоская проекция, поэтому градиент ложится ровными
  концентрическими полосами.
- **Два слоя частиц** (2600 шт.) с разной скоростью вращения (внутренний в
  ~2.2 раза быстрее внешнего — дифференциальное вращение); цвета от
  бело-жёлтого к красному, маска — общая `starTexture` без мипмапов.
- Лёгкое «дыхание»: прозрачность диска и масштаб горизонта слегка пульсируют.

Порядок отрисовки задан явно: ореолы звёзд `-0.65` → ядра звёзд `-0.6` → пыль
`-0.55` → свечение ядра `-0.5` → тёплый ореол ЧД `-0.45` → сфера `0` → диск
`0.15` → фотонное кольцо `0.2` → частицы `0.24/0.25`.

## Известные особенности / что можно доработать

- Движение системы — **иллюзия**: `world` стоит в центре, стримятся звёзды и рисуются следы.
  Так камера-наблюдатель не двигается, а система не улетает из кадра.
- `MOTION_DIR` должен совпадать для звёзд и следов (одно направление) — иначе разъедется.
- Следы строятся аналитически и предполагают, что группа `world` в начале координат.
  Если снова начнёшь двигать `world`, следы нужно пересчитывать с учётом его матрицы.
- Скорость/выдержка следов настраиваются `MOTION_SPEED`, `TRAIL_TIME` (больше = длиннее спираль).
- Глобальный множитель скорости `systemSpeed` (кнопки UI) масштабирует и орбиты, и стрим звёзд,
  и следы — чтобы иллюзия оставалась согласованной. На паузе следы не пересчитываются (не «схлопываются»).
- Туманность — сфера-скайбокс: её можно **проворачивать** (медленный `nebula.rotation.y`), но нельзя
  сдвигать/увеличивать (станут видны края или разъедется с камерой).
- Стоимость генерации текстур на старте ~1.5 c (синхронно, 9 типов планет + туманность 1280×640).
- Кольца Сатурна сделаны из полос (`createSaturnRings`); можно ещё добавить тень колец на планету.
- Спутники/аппараты — стилизованные (пропорции не физические), важна читаемость в кадре.
- Планеты двигаются по **эллипсам** с угловой скоростью по Кеплеру (`n = SPEED_FACTOR/sqrt(R³)`).
  Само `ν` двигается равномерно (как и просили в формуле), а радиус берётся из уравнения эллипса —
  поэтому следы (`trails.js`) остаются аналитически точными: планета была ровно там, где мы её считаем.
- Наклон плоскости орбиты задаётся парой `inclination` + `node` (порядок `'YXZ'`: сначала наклон,
  потом поворот узла) — так у орбиты появляется смещение по Y. Та же ориентация применяется и в
  линии орбиты, и в следах, и в анимации (единый `src/orbit.js`).
- Вращение планеты: `mesh.rotation.y += spinSpeed`. У Венеры `spinSpeed` отрицательный — ретроградное.
- Размер в карточке масштабирует только сферу планеты (кольца/атмосфера/спутники не масштабируются).
- «Скорость орбиты» в карточке — это **множитель** к кеплеровской скорости (`orbit.speedScale`),
  а не абсолютная угловая скорость. Ставишь 0 — планета останавливается на орбите.
- Пояса (~1800 тел суммарно) обновляют матрицы каждый кадр — при желании можно вынести на GPU-анимацию.
- Карточка планеты — обычный DOM поверх канваса; позиция берётся из проекции `mesh.getWorldPosition()`,
  поэтому карточка едет за планетой, но прижимается к краям экрана. Кнопка 📌 открепляет её от планеты.
- Подсказка при наведении тоже DOM: `pointermove` → `raycaster` только по видимым мешам планет.
- Солнце — единственный `ShaderMaterial` в сцене; в нём обязательны `#include <tonemapping_fragment>`
  и `<colorspace_fragment>`, иначе цвет уедет (three r186 подставляет нужные чанки для ShaderMaterial).
- Яркостная сфера (`.vignette`), сетка эклиптики и свечение фона — не участвуют в raycast и не ловят клики.
- Туман `FogExp2` действует на планеты/пояса, но у звёзд, туманности и галактики стоит `fog: false`,
  иначе дальний фон «съедается» полностью.
- Галактика — фоновая, а не часть системы: живёт прямо в `scene` (не в `world`), поэтому наклон
  системы её не крутит. Диск проходит через Солнце (мы внутри галактической плоскости), а в центре
  оставлена «дырка» `innerRadius`, чтобы рукава не лезли в планеты. Крутится вместе с паузой/«Движением».
- Камера теперь может отлетать далеко (`maxDistance` 1600, `far` 6000) — это нужно для кнопки
  «🌀 Вид» (посмотреть галактику целиком). Дальше 460 от центра сферический скайбокс прячется:
  изнутри он «обои», а снаружи — заметная сфера.
- Тумблеры: «Движение системы» замораживает орбиты, пояса, кометы, Теслу, дрейф туманности и стрим звёзд;
  «Вращение вокруг оси» — только собственное вращение планет. «Звёзды» — видимость неба,
  «Космическая пыль» — туман + свечение фона, «Сетка эклиптики» — вспомогательная сетка.
- Скрытие планеты прячет всю её группу (планета, орбита, спутники, аппараты) и её линию следа;
  клик по скрытой планете невозможен (raycast пропускает невидимые меши).
